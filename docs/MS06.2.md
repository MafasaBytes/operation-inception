# MS06.2 — Pressure Bloom deterministic conformance

## Status and boundary

PB-1.1 implements the owner-authorized rules/conformance layer only. The three
PB-1.0 traces were explicitly superseded after their stationary first-contact
loads and tangent child births proved inconsistent with PB-1.1. The revised
[rule card](MS06.md) and versioned fixture use genuine piston travel, zero initial
clocks, ordinary transitions, and computed relaxation/escape positions.

There is no rendering, audio, video, batch candidate selection, new dependency,
model, service, or format framework. No MS04/MS05 or frozen particle result is
regenerated. Technical conformance is separate from creative acceptance.

## Small implementation

- `src/inception/pressure_bloom.py`: standard-library-only controlled-state rules
  with frozen ball/parameter/event/result records, fixed 120 Hz motion, stable
  identity ordering, auditable load decomposition, sustained clocks and latching.
- `src/inception/ms06_2.py`: versioned fixture reader, expected-result assertions,
  and logical JSON command; no renderer or audio imports.
- `fixtures/ms06.2/conformance-v1.json`: explicit initial packings, seed provenance,
  chamber/ramp/schedule parameters and expected outcomes. It supplies no drive,
  load, qualifying clock or pressure history.
- `tests/test_ms06_2.py`: focused conformance, geometry, timing, ordering,
  reproducibility, bounds, reconstruction and dependency-boundary checks.
- `outputs/ms06.2/ms06.2-conformance-v1.json`: ignored logical output only, including
  fixture hash, parameters, initial state, semantic before/after records, every
  committed tick, and explicit final outcome/reason/eligibility.

All rules are in [PB-1.1](MS06.md), including the preserved wall formula
`min(1,sum(touching_ball_loads)/2)`. D derives from recorded first-contact actual
height and further actual travel divided by the explicit .16 ramp. C, D, contact
weight and L are separate facts. Compression is stylized, not physically accurate.

The engine deliberately accepts explicit packings, not a randomized layout/search
API. A seed identifies reproducible input provenance; there is no randomized
contact order. This slice does not promise useful seed-to-layout variation.
Future initialization and candidate generation remain later work, not hidden
fixture interventions. Generation-3 fixture excerpts declare their ancestry and
radius consistently; they do not claim to replay earlier births.

Events/results contain immutable JSON strings and frozen tuples. Decoding a
record yields a disposable copy. Tick samples provide continuous geometry and
load history without flooding the semantic stream. Snapshot-derived qualifications
are frozen before crush → rupture → split processing. Each cohort is ordered by
qualification tick and identity, and event-budget rollback preserves whole ticks.
Rejected non-finite inputs remain diagnostic strings; runtime invalid events
include the preceding valid state. No renderer is needed to reconstruct truth.

## Reproduction and verification

From the repository root (Windows: use `.venv\\Scripts\\python.exe` instead):

```bash
PYTHONPATH=src .venv/bin/python -m inception.ms06_2
.venv/bin/python -m pytest -q tests/test_ms06_2.py
.venv/bin/python -m pytest -q
.venv/bin/python tools/verify_particle_freeze.py
git diff --check
```

Only the first command writes the single authorized MS06.2 logical output. It
never invokes an old exporter. Repeating it with unchanged fixture/code produces
identical JSON in the same numeric environment. Outputs remain ignored by Git.

## Limitations and creative risks

The microfixtures prove local rule consequences; they do not demonstrate that the
nominal 24-ball schedule produces a watchable 14–18-second spectacle. A seeded
initial packing generator and candidate search have not been built. Two-to-three
lineage color semantics are identities only, with no team victory.

Smooth travel drive does not smooth topology changes. A new contact may change
load sharply, and the 64-pass projection budget may stall an otherwise feasible
packing. Moderate loads can persist at a stalled actual height. Generation/cap
blocking can stop multiplication without producing a dramatic ending; finite
packing stalls remain draws. The narrow reversal fixture illustrates a real
contact trap, not a guaranteed frequency of desirable reversals.

More compression is not monotonically closer to rupture: the same rupture
fixture driven to .24 instead of .28 crushes a supporting ball, relieves wall
stress, and contains the remainder. This is genuine vulnerability/reversal, but
could also make a later clip confusing. Disks have no gravity, and release is an
explicit prescribed impulse, so visual clarity must be tested rather than claimed.
Floating arithmetic is replayed deterministically on the same Python/platform;
bitwise cross-platform geometry equivalence is not promised.
